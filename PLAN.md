## Original overview (from reading upstream @ 34d1a36)

`watchgha` is a Python terminal application that watches GitHub Actions runs on a branch. It resolves a repo (local dir or GitHub URL) + branch into GitHub API URLs, repeatedly fetches workflow runs and their jobs, groups runs into "events", renders a live table (rich), and refreshes until all jobs finish. Entry points: `watchgha.watch_runs:main` (the `watchgha` command) and a deprecated `watch_gha_runs` wrapper.

The finalized original-deps → Rust mapping is recorded in the Progress snapshot above.

Environment variables the original reads:

- `GITHUB_TOKEN` — bearer auth (else `.netrc` via httpx `NetRCAuth`)
- `GITHUB_SERVER_URL` (default `https://github.com`) — used to parse remote URLs
- `GITHUB_API_URL` (default `https://api.github.com`) — base for API calls
- `SAVE_DATA` — if `1`/truthy int, dump every fetched payload to `get_NNN.<ext>` and index them in `get_index.txt`

## Functional alignment audit (post-ship differential pass)

A full functional-alignment audit of the Rust port against the original CLI (upstream @ 34d1a36, oracle = `.oracle-venv/bin/watchgha` 2.7.0), scoped per the porting contract to **command-line functional behavior only** — argument/subcommand surface, argument-combination logic, functional I/O results, exit codes, env-var reads, config loading, and stdin/stdout/stderr behavior. Help text, log wording, error-message phrasing, and stack traces are excluded as non-functional (INV-PARITY); where a difference is both functional and textual, the functional logic decides.

**Method.** Three independent read-only differential source audits (HTTP layer; data-aggregation + rendering; git/URL/time/watch-loop), each citing `file:line` on both sides, cross-checked against the oracle empirically and against the full gate suite: G-FMT/G-LINT exit 0, G-TEST 42/42, G-PARITY 13/13, plus oracle-vs-Rust exit-code comparison across the option surface (`--version`, unknown flag, bad `--poll`, extra positionals) and the runtime fatal paths (nonexistent repo, URL-repo-needs-branch, not-a-git-dir — all exit 1 on both).

**Result.**

- **Aligned (functionally identical, drop-in):** the option/argument surface (`--sha`, `--poll` default 15, `--wait`/`--wait-for-start` alias, `--only` split+trim+case rule, `--message`, `REPO` default `.`, `BRANCH` optional), URL/GIT resolution and the URL regex (https/SSH/enterprise/`.git`/trailing-slash), query-param build + urlencode order, env reads (`GITHUB_TOKEN`/`GITHUB_SERVER_URL`/`GITHUB_API_URL`/`NETRC`/`SAVE_DATA`), HTTP auth + retry backoff formula, dedupe/sort/group/`.github`-drop/7-day/`--only`-filter/status-totals, render field order/widths/stepdots/control-char scrub, `nice_time`/`to_datetime`/`human_key`/`defuzz` (incl. Python half-to-even rounding), watch-loop interval accounting/alt-screen/SIGWINCH/OSC 9;4, exit codes (0/1/2), and the deprecated `watch_gha_runs` entry point (delay math + date).
- **待对齐差异点 (functional divergences, all portable — registered as `D` rows):** the `D` register. Three were found by this audit, and **all three are now fixed** on `slice/fix-audit-divergences`: **D-12** (job sort omitted `defuzz` → same-bucket jobs ordered by time not name; `DATA-8` was wrongly `direct match`) → fixed, recorded as **B-6**; **D-11** (`--poll -5` space form rejected with exit 2 vs the original's exit 1) → fixed, recorded as **B-7**; **D-10** (SAVE_DATA extension narrower than `mimetypes`) → fixed for all common MIME types and narrowed to its irreducible `mimetypes`-platform-dependence residual (an ecosystem limitation, kept as a narrow `D`). `DATA-8` and `OPT-POLL` reverted to `direct match`. D-1…D-9 are the previously-registered, deliberately-accepted divergences.
- **无法移植功能点:** **none.** 经全量校验，原版 CLI 所有命令行功能均不存在 Rust 语言/生态层面的移植障碍，无无法移植功能点。`N-1` (`watchgha.demo`) is excluded by scope (dev-only `python -m` helper, outside the shipped-CLI contract), not by any Rust constraint. Every functional divergence above is technically portable and carries a fix point.

**Findings rejected after validation (not registered):** the HTTP audit proposed that the port newly honors proxy env vars (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY`) while the original ignores them. Reproduced and **refuted**: `httpx.AsyncClient(auth=self.auth)` (`http_help.py:48`) sets no `trust_env=False`, and httpx 0.28.1 defaults `trust_env=True` (verified: proxy mounts populated when `HTTPS_PROXY` is set); reqwest 0.13.5 likewise reads proxy env by default (`Proxy::system()` → `Matcher::from_system()`, `NO_PROXY` handled at `proxy.rs:477`). The two align — false positive.
